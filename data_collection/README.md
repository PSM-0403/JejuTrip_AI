# 데이터 수집 과정

앱이 사용하는 `jeju_crawling_100.csv`를 만든 수집·정제 노트북입니다. 프로젝트 기간(2026.03.31 ~ 04.07)에 작성한 노트북을 실행 순서대로 정리했습니다. 노트북 코드와 실행 결과는 당시 그대로이고, 파일 이름과 API 키 처리 방식만 바꿨습니다.

## 실행 순서

| 순서 | 노트북 | 하는 일 | 결과 |
|---|---|---|---|
| 01 | `01_tourapi_place_list.ipynb` | 한국관광공사 TourAPI로 제주 관광지 목록 수집 | 관광지 목록 |
| 02 | `02_clean_place_list.ipynb` | 장소명 키워드로 숙박·관공서·병원·마트·브랜드 매장 등 제외, 추자도·마라도 및 위도 범위 밖 좌표 제외, URL 중복 제거 | 1,394곳 → 1,234곳 |
| 03 | `03_crawl_kakao_reviews.ipynb` | 카카오맵 장소 페이지에서 평점, 후기 수, 블로그 수, 리뷰(최대 30개) 수집 | 1,234곳 |
| 04 | `04_find_failed.ipynb` | 후기 수는 있는데 리뷰 텍스트가 비어 있는 곳 추출 | 51곳 |
| 05 | `05_recrawl_failed.ipynb` | 04의 장소를 대기 시간을 늘려 다시 수집 | 51곳 |
| 06 | `06_merge_recrawl.ipynb` | 재수집 결과로 빈 리뷰 채우기 | |
| 07 | `07_merge_and_filter.ipynb` | 장소 정보(좌표·주소·URL)와 수집 결과 병합, 후기 수 기준 필터 (10개 이상 952곳 / 5개 이상 1,057곳) | 1,057곳 |
| 08 | `08_keywords_and_category.ipynb` | Okt 명사 키워드 추출, 키워드 규칙으로 카페 재분류, 오분류 수동 수정 | |
| 09 | `09_crawl_final_reviews.ipynb` | 직접 확인해 확정한 최종 목록(1,054곳)의 리뷰 재수집 (재시도 3회, 50곳마다 백업) | `jeju_crawling_100.csv` |

07 이후 1,057곳 중 3곳은 직접 확인해 제외했고, 이 과정은 노트북이 아닌 수작업으로 진행했습니다. 09에서 1곳은 리뷰를 수집하지 못했습니다.

## 실행 전 참고

- 중간 단계 CSV 파일은 저장소에 포함하지 않았습니다. 노트북은 같은 폴더에 이전 단계 CSV가 있다고 가정합니다.
- 01은 `.env`에 `TOUR_API_KEY`가 필요합니다 (`.env.example` 참고).
- 03, 05, 09는 Selenium과 Chrome이 필요하고, 카카오맵 페이지 구조가 바뀌면 동작하지 않을 수 있습니다. 앱 실행에는 필요하지 않아 루트 `requirements.txt`에는 넣지 않았습니다 (`selenium`, `webdriver-manager`, `tqdm`, `konlpy`).
